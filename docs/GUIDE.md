# 动态 JS 与标签渲染玩法指南

## 一、基本使用

v2.3.2 首次安装的标签规则均为“指定角色”且选择为空。请先编辑各规则的角色范围、保存并应用设置。升级不会清空已有绑定；动态 JS 仍须单独选择角色和启用。

插件详情 → 标签渲染配置 → 动态 JS 注入。切换预设只切换编辑对象，不会把四套一起执行；每套脚本分别保存。编辑后先“检查 JS 语法与环境”，再“试运行”，最后保存。

检查只编译，不执行用户代码，因此只能排除语法和基础环境错误；运行中才会触发的未定义 API、非法返回值、死循环等要通过试运行确认。试运行使用当前未保存草稿，结果不进入聊天。

正式启用需要同时满足：动态开关开启、匹配角色范围、主 CHAT 请求、可识别的角色卡身份。未选任何角色时仍能试运行，但正式请求不注入。只处理 `before_send_to_model`，不在 token 估算阶段运行。

返回按钮会放弃未保存修改；再次进入会重读已保存配置。v2.3.1 已修复首次进入卡在“正在读取配置”的问题。

## 二、四套预设

| 预设 | 默认输出 | 主要可调项 |
|---|---|---|
| 随机码 | 3 行，每行 20–40 个字符 | 段数、长度、字符池、join 分隔符 |
| 时间 | 当地日期时间、偏移、时区 ID | 输出格式和页面时区设置 |
| 自定义 | 空字符串 | 完全自行编写 JS |
| 每日主题＋微事件 | 当日主题、可选事件、因果约束 | themes、events、eventChance |

随机码的最简脚本：

    return randomCodes(3, 20, 40).join("\n");

同时注入随机码与时间：

    const t = now();
    return randomCodes(3, 20, 40).join("\n") + "\n" + t.local;

除了脚本返回文本，插件不增加任何说明。新预设里的“今日主题”是 JS 输出的一部分，不是插件强制前缀。

### 每日主题＋微事件

默认七个主题按日序号轮换，七天一周期。日期由页面选定时区的 `now().date` 决定；同日同脚本主题固定。更改主题数组、日期或时区可能改变主题。默认所有匹配角色共享相同主题算法，不是每个角色独有主题。

- `eventChance = 0.15`：每次新请求 15% 概率，不是每七轮必有一次。
- 改成 `0`：只保留主题；改成 `1`：每次附带一个事件。
- 编辑 `themes` 与 `events` 的字符串即可换题材，数组不要留空。
- 没有持久化计数：**不支持“当天只触发一次”或事件完成状态**。多次请求可能连续触发或重复。
- 同请求携带插件标记的重复组装会复用结果；新请求及试运行重新抽取。新请求中日期未变时主题仍固定。
- 默认文案要求“不符合场景则忽略”，但脚本本身看不到聊天，需要模型结合已有上下文判断。

完整可编辑脚本见 [组合预设](../examples/daily-theme-microevent.js)。

## 三、七类玩法

以下文件都是**脚本函数体**：复制完整内容到自定义编辑框，不要额外包函数，不要直接当 Node 模块运行。

### 1. 角色生活日程

[示例：routine.js](../examples/routine.js)

按 `now().time` 的小时区分夜间、上午、下午、晚间，给出轻量日程参考。现实时间未必是剧情时间，因此示例明确不强制跳转场景。无法读取角色职业或当前剧情；更细的日程请手工写在脚本数组/条件中。

### 2. 每日固定主题

[示例：daily-theme.js](../examples/daily-theme.js)

适合让同一天的交互保留轻微连续感。日期映射为日序号后按主题数量取模，不用全局变量保存，也不依赖不支持的 Intl。更换时区可能跨日，不应期待各地午夜同时换题。

### 3. 小概率随机事件

[示例：microevent.js](../examples/microevent.js)

85% 概率返回空字符串，15% 概率给出一个可选生活插曲。用 `return "";` 可以做到“本轮完全不增加内容”，比每轮都写“没有事件”更简洁。事件不应无视已成立的地点、人物状态或因果。

### 4. 骰子检定

[示例：d20.js](../examples/d20.js)

    const roll = 1 + Math.floor(Math.random() * 20);
    const dc = 12;
    return "D20=" + roll + "；难度=" + dc + "；" + (roll >= dc ? "成功" : "失败");

适合游戏判定/写作分支提示。每次请求掷骰，不是读到某个行动才掷骰；脚本无法知道当前是否需要检定。需要模型严格裁定时另行制定规则，此处只是提供文本结果。

### 5. 随机人物/场景细节

[示例：detail.js](../examples/detail.js)

从语气、停顿、手边物品、光线等观察角度抽一个，避免直接生成与人设冲突的事实。也可改成用户已经确认存在的服饰、习惯列表。由于不能读取聊天，不具备跨轮状态维护能力。

### 6. 写作挑战卡

[示例：writing-challenge.js](../examples/writing-challenge.js)

随机选“用动作表现情绪”“用对白推动信息”等小要求。适合写作练习，不适合把互相冲突的十条要求每轮全部塞给模型。示例要求优先服从用户当前写作任务。

### 7. 每日任务/练习

[示例：daily-practice.js](../examples/daily-practice.js)

按日期轮换写作/编程练习。只提供任务，不记录完成与连续天数，也不会定时主动发消息；只有用户发起匹配请求时才运行。若要任务打卡与提醒，需要另行接入持久化和定时功能。

额外基础示例：[随机码](../examples/random-codes.js)、[时间](../examples/time.js)。共 10 份示例均进入本地执行测试。

## 四、时区与辅助函数

关闭“跟随设备时区”后，填写 `Asia/Shanghai`、`Asia/Tokyo`、`America/New_York`、`UTC` 或 `+05:30` 等。不要写含糊的 `CST`；是否有效以“检查/试运行”反馈为准。

地区时区按设备时区数据库处理夏令时；固定偏移不随季节变化。修改页面时区影响 `now()` 与 `context.time`，**不会重设标准 `Date` 的系统本地时区**。需要所选时区时不要用 `new Date().getHours()` 替代 `now().time`。

`now()` 同次执行返回同一不可变快照：

| 字段 | 含义 |
|---|---|
| `epochMs` | Unix 毫秒时间戳 |
| `iso` | 带偏移的 ISO 时间 |
| `local` | 当地 `yyyy-MM-dd HH:mm:ss` |
| `date` | 当地 `yyyy-MM-dd` |
| `time` | 当地 `HH:mm:ss` |
| `offset` | `+08:00` 或 `Z` 等 |
| `timeZone` | 本次解析出的时区 ID |

`context.time` 是同一快照，不包含聊天、角色详情、天气或地理位置。

`randomCodes(count, minLength, maxLength, charset)` 返回字符串数组，默认 `3, 20, 40, DEFAULT_CHARSET`。原字符池共 324 个字符；选择字符使用宿主 SecureRandom。示例的 `Math.random()` 用于非安全性玩法，不适用于密码、抽奖公证等用途。

## 五、常见问题

| 现象/错误 | 处理 |
|---|---|
| `JS_SYNTAX` | 检查引号、括号、逗号与 return 写法 |
| `JS_RUNTIME` | 查看错误栈；检查数组和变量是否存在 |
| `ENV_UNSUPPORTED` | 不使用 require、fetch、Tools、Java、Intl、DOM、定时器等宿主未开放 API |
| `TIMEZONE_INVALID` | 改为有效地区 ID 或固定偏移 |
| `INVALID_RESULT` | 必须返回字符串；数值用 String，结构用 JSON.stringify |
| `JS_TIMEOUT` | 去掉无限循环或永不完成的 await；执行预算约 1.5 秒 |
| `OUTPUT_LIMIT` | 缩短生成内容至 16384 个 UTF-16 码元以内 |
| `CONFIG_CONFLICT` | 配置 revision 已变，重新读取再编辑；先另存草稿 |
| `BUSY` | 当前执行槽位已满，稍后重试 |
| 试运行正常但未注入 | 检查总开关、保存、角色范围和当前是否主角色对话 |
| 返回空串 | 正常：本轮不新增注入消息 |

代码可使用 Promise/await，但不能据此访问网络或定时器。不支持持久化变量、`set_var`、聊天检索和跨日事件冷却。不要用死循环模拟计时，不要运行不可信的大内存脚本。

## 六、标签渲染与正则

入口：标签渲染配置 → 编辑标签 → 正则替换。新增规则后先测试、应用到替换列表，再返回保存整条标签规则。

例如 pattern 填 `姓名[：:]([^\n]+)`，flags 填 `g`，replacement 填 `$1`。pattern 不要额外包 `/.../g`。支持 g/i/m/s/u 和捕获组替换模板，替换模板不执行 JS。

正则只处理已匹配标签的显示正文；不处理整条 AI 回复，不修改历史或变量块。隐藏/安全回退路径不替换。选项点击会填入替换后的整行，“复制原文”仍复制原始标签块。

最多 16 条规则；分组整体重复、模式反向引用、前后查找受限。复杂正则没有硬超时，仍须只用可信规则。外观字段与参考链接见 [图标和颜色说明](APPEARANCE.md)。
