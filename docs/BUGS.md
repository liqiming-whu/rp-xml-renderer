# Bug 与技术决策记录

## BUG-20261029-01：动态注入首次进入卡加载

状态：**已关闭；本地与真实宿主 Compose action 回归通过，用户于 2026-10-29 确认实机测试通过。**

### 复现

打开标签配置，宿主自动执行根 `onLoad`。点击动态 JS 入口后显示“正在读取配置…”，必须点“重新读取”才加载。

旧版反证：历史首次导航反证探针（仅本地归档） 只触发一次根 onLoad 后点击入口，返回 `ready:false`，182ms。初次尝试通过 Tools.Files 读取再 eval 探针失败（TypeError），没有把这次工具错误当成业务复现；随后直接运行独立探针文件才得到有效证据。

### 已证实根因

本机宿主 `ToolPkgComposeDslScreen.kt` 的 `hasDispatchedInitialOnLoad` 控制根 onLoad 每个 screen 实例只自动调度一次（调研源约 1491–1500 行）。`settings.ts` 内联返回动态子页仍是同一实例，因此换根 key 也不能再触发自动加载。

不是已证实的 SharedPreferences 慢读、Promise 丢失或 setData/setStatus 竞态。旧版 UI 探针（仅本地归档） 在导航后手动调用第二次 onLoad，绕过了真正的宿主行为，造成漏测。

### 修复

- 父页无条件注册 `useInjectionPage(ctx)` 状态。
- 入口 action 先 `injectionPage.read(data.cards)` 再切页。
- 复用父页已经加载的角色列表；手动重新读取仍可刷新角色列表。
- 每次重新进入读取已保存配置，丢弃草稿；读取失败明确显示错误和重试，不无限假装加载。
- 子页 onLoad 保留作防御路径，但导航不再依赖它。

### 回归

- 首次导航无需额外 onLoad 即 ready=true。
- 返回再进入无需额外 onLoad，未保存草稿丢弃。
- 读取失败可见、手动重试可恢复（本地故障注入）。
- 宿主 v231 UI 探针：四预设试运行、语法/环境/时区错误、超时约 1511ms 后恢复，配置前后不变。
- 用户后续明确反馈“实机测试通过”，并提供 README 中的两张界面截图；不将截图单独当作真实模型生成测试证据。

## DEC-20261029-01：第四套预设保持 schema 2

四个按钮改为纵向排列，以免长预设名挤在同一行；不扩大其他标签布局改动范围。

## 已知技术债

- 用户脚本没有硬堆内存配额；隔离上下文不是进程隔离。
- 同步正则执行虽有限额/语法保护，但没有硬超时。
- 旧的设备专用探针不随公开源码分发；公开 probes 使用当前入口，不含真实会话定位。
- 主题与事件无持久化，跨轮“已发生”只能交由模型上下文判断。
- 图标格式有效不保证宿主类存在，当前由宿主回退 Info。
